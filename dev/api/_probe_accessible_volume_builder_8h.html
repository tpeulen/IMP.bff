◆ element_symbol_from_pdb_line()

IMPBFFEXPORT std::string element_symbol_from_pdb_line ( const std::string & line)

The element symbol of a PDB ATOM/HETATM record.

Columns 77-78 carry it in a modern PDB and are used verbatim when present. Older files — the shipped FPS screening structures are 66-character records — leave them empty, so the element comes from the atom-name field, where it is right-justified in columns 13-14: a blank or numeric column 13 means a one-letter element, so " CA " is an alpha-carbon while "CA " is calcium. A two-letter reading is additionally rejected when columns 15-16 contain a digit, which is how a four-character hydrogen name such as "HE21" is written — helium would otherwise win.

An accessible volume from a PDB file and an attachment atom, with no IMP.

The file front door of the core, one call the way labellib's dyeDensityAV3 is one call: the structure's atoms with IMP's radii times radius_scale (load_structure_with_vdw), the attachment atom's position (get_attachment_point), then get_av. This is the road the Labelizer's AV-mode sites take under the standalone build.

The IMP module build also has get_av_from_structure (ProbeAccessibleVolumeDecorator.h), which reads the structure through IMP::atom. Both roads take IMP's radii times the same scale (owner, 2026-10-12: one atom-radius set); they still differ in which atoms they read – this door reads every record, waters and all, while the structure door drops waters and strips the attachment residue.

An accessible volume from a structure as IMP reads it: the structure front door.

The attachment residue is stripped (#IMP::bff::stripped_pdb_for, with strip_mask), then the atoms are read the way IMP::atom::read_pdb with a NonWaterPDBSelector reads them – the first model only, the alternate location blank or A, no HOH/DOD – each inflated by IMP's radius (#IMP::bff::imp_atom_radius) times radius_scale, and the lattice search (get_av_lattice) runs from the attachment atom. The point weights are forced to one except for an accessible contact volume (contact_volume_thickness > 0 and a trapped fraction in [0, 1)), whose weights are the answer.

One implementation for both builds: the IMP module build used to read the structure into an IMP::Model and resample a decorated particle, which made contact volumes unreachable from the standalone build; that route computes the same volume (test/test_av_structure_door.py holds them equal).

The same front door, from an fps.json Positions entry.

A position is data, so this takes it as data (JSON text), not as separate keywords. The entry's fields – chain_identifier, residue_seq_number, atom_name, linker_length, linker_width, radius1..radius3 (an AV3 position's absent radii are FPS's three, av_position_radii), strip_mask, allowed_sphere_radius, contact_volume_*, radius_scale and simulation_grid_resolution – are read the way the fps dictionary states them, and a declared simulation_grid_resolution that disagrees with disc_step raises: that field would otherwise be silently overridden.

The accessible-volume search over spheres, without an IMP::Model.

The decorator's lattice path (ProbeAccessibleVolumeDecorator::resample_lattice_*) as one call over a list of (x, y, z, radius) spheres: the window, the two occupancy rasters, the attachment-atom subtraction, the bounded search, the dye-radius carve and the contact weighting, then the read-out. source_radius is the radius of the sphere at the attachment site (0 when none is there), the one the raster subtracts around the source so the linker is not blocked by the atom it is tied to. search_stencil is 342 (the default, FPS's link search: the 3-voxel cube hop from every node), 74 (the seed-only "fast" search, the reference metric) or 26; allowed_sphere_radius defaults to #IMP::bff::AV_DEFAULT_ALLOWED_SPHERE and < 0 derives the clearance as the decorator does. get_av() is this over a caller's (N, 4) array.

The shortest linker path to every voxel, LabelLib's minLinkerLength.

The same lattice search get_av_lattice runs, read out as path lengths instead of as an accessible volume: each voxel carries the length of the shortest obstacle-free linker path from the attachment atom to it, and a voxel the linker cannot reach carries a negative value. The grid is the volume's grid – same origin, same spacing, same (x, y, z) order.

(N, 4) of x, y, z, radius — the obstacle array the solver takes.

Every ATOM/HETATM record (read_pdb_records), its radius IMP's (#IMP::bff::imp_atom_radius, by residue and atom name) times radius_scale – the one atom-radius set an accessible volume uses at every door (owner, 2026-10-12), so this file door and the structure door (get_av_from_structure) inflate the same atoms by the same numbers. It used to be Bondi's element table (vdw_radii), FPS's set, a second radii set the scale was fitted to replace.

Parameters
