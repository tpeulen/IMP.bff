Bonds from geometry, by a covalent-radius cutoff.

A guess, and that is why it is not the default: CONECT records are what a PDB says, and this is what a distance suggests.

The rule is perceive_bonds': bonded when the separation is under over covalent_radius. This used to be a second table (Cordero radii) under a multiplicative rule, which agreed with the first on every molecule in the tree but not on the cutoffs – C-H at 1.31 A against 1.49 A – so a stretched bond was a bond or not depending on which function was asked.

Parameters
[in]toleranceadded to the sum of the two covalent radii

IMPBFFEXPORT void read_score_series ( const std::string &  stat_path,
double **  out_view,
int *  n_out_view 
)

(frames, scores) from a PMI stat file or a frame,score CSV.

The ReplicaExchange macro appends one repr(dict) per frame to stat.0.out, after a first header line whose values name the columns. Only two columns are wanted — the frame index and the total score — so the parsing is deliberately tolerant: an unreadable line is skipped, including the header itself, which carries an environ(...) call no literal parser accepts.

A partial file from a running job is fine, and so is the plain frame,score CSV a minimisation writes.

Parameters
[out]out_view,n_out_viewtwo values per point: frame, then score

Write a scalar grid as an MRC2014 map.

The volumetric format ChimeraX, PyMOL, mrcfile and IMP::em all read, and the sibling of #IMP::bff::write_opendx above: same arguments, other format. It is the array door to the writer #IMP::bff::DensityGrid::write_mrc uses, for a caller that has a dense grid rather than a DensityGrid – filling one from Python would cost a wrapped call per voxel.

Values run in C order here, (nx, ny, nz) with z fastest, and are transposed on the way out because MRC specifies x fastest. That is the same convention #IMP::bff::write_opendx takes, so the two are interchangeable at the call site.

Parameters
[in]pathwhere to write
[in]densitythe grid, nx * ny * nz, in C order
[in]nx,ny,nzthe grid shape
[in]originthree coordinates of the lowest corner, A
[in]spacingthe grid step, A
Exceptions
ValueExceptionon a shape mismatch, or a spacing that is not positive and finite
IOExceptionwhen path cannot be opened

IMPBFFEXPORT std::string write_points_mrc ( const std::string &  path,
double *  points,
int  n_points,
int  n_columns,

Write a weighted point cloud as an MRC2014 map, voxelising it first.

An accessible volume, a dye's sampled positions, any (N, 4) cloud: the points are binned onto a grid of grid_step, weights summed per voxel, and the grid written with #IMP::bff::write_mrc_grid. The origin is the cloud's own minimum corner and the shape is whatever the cloud spans, so nothing has to be said about extent.

The rounding is rint((xyz - origin) / step), which puts a point at the centre* of its voxel rather than at a corner – the same convention the accessible-volume raster uses, so a cloud that came from one lands back on it.

Parameters
[in]pathwhere to write; .mrc is appended unless the path already ends in .mrc, .map or .ccp4
[in]pointsflat, three or four per point: x, y, z and optionally a weight. Without a weight every point counts once.
[in]n_points,n_columnsthe shape, (N, 3) or (N, 4)
[in]grid_stepthe voxel spacing, A
Returns
the path actually written
Exceptions
ValueExceptionfor an empty cloud, a column count that is not 3 or 4, or a grid step that is not positive and finite
IOExceptionwhen the file cannot be opened
