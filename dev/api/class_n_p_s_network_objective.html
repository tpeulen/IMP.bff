Detailed Description

The Fast-NPS network posterior as a MCMCSampler objective node.

One GraphNode whose update() builds the configuration rows from its linked input ports — one scalar port per dye coordinate (MCMCSampler's parameter ports are scalar), three per dye, the angles seeded isotropic at — evaluates the committed nps_network_log_likelihood() (or nps_network_chi2() in chi2 mode) and publishes the value on the "chi2" output port. set_output_is_log_likelihood() selects the reading: the default publishes (MCMCSampler's native objective currency), log-likelihood mode publishes the actual normalized on the legacy-named "chi2" port. The sampler must then read that port with its own set_output_is_log_likelihood(true); it treats the value as and reports as its chi2 record.

Because the node fixes the dye angles and links no angle ports, it can only sample a position-only posterior. Construction therefore rejects orientation-dependent likelihoods: direct FRET requires dep = 0 for both dyes of every active pair ( , the fully depolarized dye-model-2 chemistry of Muschielok & Michaelis 2011), distance-convolved FRET requires an iso/iso pair (row 0), and transfer anisotropy requires . Measurement dye indices must address the dye array. Violations raise IMP::ValueException at construction instead of silently conditioning the posterior on the frozen orientation.

This is the whole Fast-NPS sampling objective without a Python std::function and without a per-move crossing: the ports link to the sampler's parameter ports, so a proposal lands here by reference and update() is pure C++. The dyes and measurements are copied at construction and never change.

Exceptions
IMP::ValueExceptionat construction when n_dyes is not positive, a measurement references a dye outside the array, or an active observable depends on the frozen dye orientation.
