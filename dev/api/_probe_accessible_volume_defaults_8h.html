The allowed sphere, A: the clearance around the attachment atom inside which the linker ignores obstacles. On by default (owner, 2026-10-12: "allowed sphere radius must be enabled by default"), at FPS's value: LinkerInitialSphere (0.5, ProjectData.cs:169) times FPS's first-preset linker width (4.5, Fps/data/linker.txt row 1; every FPS preset has it), i.e. 2.25 A. It is the default of every typed door's allowed_sphere_radius. A door that reads a position – the fps.json readers, the command line – takes FPS's rule for that position's own width instead, LinkerInitialSphere * W (av_derived_allowed_sphere_radius), which is this value at the default width: FPS's screening document has widths of 2.5, 3.5 and 4.5 A, and a flat 2.25 for all of them moved 3GUN away from FPS. A negative value means that rule at any door.

◆ AV_DEFAULT_RADIUS_SCALE

constexpr double AV_DEFAULT_RADIUS_SCALE = 0.84
constexpr

The one factor IMP's radii are scaled by as an AV's obstacle set.

FPS inflates its obstacles by element-keyed Bondi radii (vdW.txt); IMP's particles carry CHARMM united-atom radii with implicit hydrogens, ~17 % larger (carbon 1.85-2.275 A against 1.70). Owner, 2026-10-12: "i do not want a separate set of atom radii, if fps is slightly smaller, use a single scale factor to match fps radii". So the AV keeps IMP's radii – the ones on the particles – and multiplies them by this one number; there is no second radii table. Fitted to FPS, not inferred (okf/validation/fps_screening_ab.md, "AV obstacle-radius scale"): over the 20 434 heavy atoms of 148L, 3GUN and 1RTD the FPS/IMP radius ratio is 0.838 (median; least squares 0.821), and on T4L 148L's CB sites the volume against FPS's own routine is 1.00 at this value (0.91 at 1.0). Applies to radii_source = "imp" only: Olga's table is used as published. Every door that reads IMP's radii for an AV takes it (decorator, fps.json position field radius_scale, the docking restraint); the array doors take the caller's radii as given. The docking clash term is separate (DockingParameters::clash_radii_scale, 1.0).
