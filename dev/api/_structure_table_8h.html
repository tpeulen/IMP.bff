Read a PDB or mmCIF into a #IMP::bff::StructureTable without IMP.

The core's reader for the table read_structure_table fills through IMP::atom – the same atoms, in the same order, with the same numbers, so a caller that has only the core reads a structure the way the IMP module build does. What it reproduces, rule by rule:

  • the atom set of IMP's default selector: every ATOM and HETATM record, hydrogens and ligands included, except water (HOH, DOD) unless keep_water, and except alternate locations other than blank or A. Only the first model: a PDB is read up to its second MODEL record, an mmCIF's rows of any other pdbx_PDB_model_num are skipped.
  • the order: chains in file order and residues sorted by number within a chain. A PDB chain is a run of one chain identifier, so a chain that comes back after another (ligands after TER) is a chain of its own; an mmCIF chain is one author chain identifier however its rows are spread. The sort is stable, so residues sharing a number (insertion codes) keep their file order.
  • the numbers: coordinates and B-factors at single precision, as IMP stores them; the residue number of a PDB as a 16-bit integer; an mmCIF residue's number and insertion code from auth_seq_id (12B is 12, B), falling back to label_seq_id.
  • the element from the element column, else from the atom name by IMP's rule (the first letter of an ATOM name, the first two of a HETATM name); Un, mass 0, when neither names one. The mass is IMP's element table.
  • the radius #IMP::bff::imp_atom_radius by residue and atom name – the radius IMP::atom::read_pdb gives the particle – rounded to single precision as IMP's CHARMM table stores it. An atom CHARMM leaves untyped (a ligand's) IMP gives exactly 1.7 where this gives 1.7 at single precision, 5e-8 A apart.
  • the atom name without IMP's HET: prefix, as read_structure_table reports it.

atom_id is the record's serial number (_atom_site.id).
