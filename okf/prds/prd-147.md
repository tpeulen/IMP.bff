# PRD-147: one sampler interface in bff

**Author:** Claude Opus 5 for tpeulen. **Written:** 2026-09-15 16:40 CEST.

**Owner** (tpeulen, ucfret prompts 465-467): "shouldnt the sampler be in bff not tttrlib?", "cant you
design a common sampler interface?", and, on moving `McmcDiagnostics.h` along with `NoUTurnSampler.h`:
"both".

## Why

bff samples in two places that share nothing:

- **`MCMCSampler`** (`include/MCMCSampler.h`, `src/MCMCSampler.cpp`, 1636 lines).
  - Four algorithms behind an algorithm string: stretch, DE, ensemble slice, blocked Metropolis.
  - The objective is value-only: a `GraphNode` chi2 / log-likelihood, or a
    `std::function<double(x)>`.
  - It carries bounds, priors, warm-up, the chain and acceptance bookkeeping, all in one class.
  - Used by chisurf (`chisurf/core/fitting/sampler_bff.py`) through SWIG.
- **`BayesianDecaySampling.h`.**
  - One NUTS chain through tttrlib's `NoUTurnSampler`, with its own chain struct.
  - Its own convergence summary through tttrlib's `McmcDiagnostics`.

The warm-up machinery exists twice: Stan's windowed schedule and dual averaging in `MCMCSampler.cpp`
(`adaptation_windows`), and dual averaging again in `NoUTurnSampler`. The dense metric adaptation that
PRD-146 needs next would make it three. Neither sampler nor the diagnostics has a user in tttrlib, so by
the placement rule (Bayesian inference in bff; prompt 452 item 8) both move to bff.

## The design

Five pieces. Each can be tested on its own, and each has exactly one implementation.

### 1. `SamplingTarget`: what is sampled

```cpp
struct SamplingTarget {
  std::size_t dim = 0;
  std::function<double(const std::vector<double>& x)> log_density;                      // required
  std::function<double(const std::vector<double>& x, std::vector<double>& grad)> log_density_gradient;  // optional
  std::vector<double> lower, upper;          // optional box; empty = unbounded; outside = -inf, never clipped
  std::vector<std::string> names;
  bool has_gradient() const;
};
```

Adapters, one function each:
- `sampling_target(std::function<double(x)>)`: a plain function.
- `sampling_target(f, f_and_grad)`: a function with its gradient.
- `graph_sampling_target(ports, node, output, output_is_log_likelihood, temp, chi2max)`: what
  `MCMCSampler::evaluate` and `log_prior` do today (box, port priors, `-chi2/2`, the chi2max cutoff).
  This code moves; it is not rewritten.
- `bayesian_decay_sampling_target(f, env)`: `bayesian_decay_log_posterior_and_gradient`.

**No silent finite differences.** A kernel that needs a gradient refuses a target without one, with
`SamplerConfigurationError`. Finite differences are available only through the named, explicit adapter
`with_finite_difference_gradient(target, h)`.

### 2. `SamplerKernel`: one transition

```cpp
class SamplerKernel {
 public:
  virtual ~SamplerKernel() = default;
  virtual std::string name() const = 0;
  virtual bool needs_gradient() const { return false; }
  virtual bool is_ensemble() const { return false; }     // walkers interact (stretch, DE, slice)
  virtual void initialize(const SamplingTarget&, const std::vector<std::vector<double>>& walkers, std::mt19937_64&) = 0;
  virtual void transition(std::mt19937_64&) = 0;          // every walker once
  virtual const std::vector<std::vector<double>>& walkers() const = 0;
  virtual const std::vector<double>& log_density() const = 0;
  virtual void begin_warmup(const WarmupSchedule&) {}
  virtual void end_warmup() {}
  virtual std::vector<std::string> stat_names() const = 0;           // Stan-style per-draw statistics
  virtual void stats(std::vector<double>& per_walker_row_major) const = 0;
  virtual long evaluations() const = 0;
  virtual std::unique_ptr<SamplerKernel> clone(std::uint64_t seed) const = 0;   // fresh, same settings
};
```

The kernels:

| kernel | kind | statistics |
|---|---|---|
| `NutsKernel` | chain | `step_size`, `tree_depth`, `n_leapfrog`, `divergent`, `accept_stat`, `energy` |
| `BlockedMetropolisKernel` | chain | `accepted` per block |
| `StretchKernel` | ensemble | `accepted` |
| `DifferentialEvolutionKernel` | ensemble | `accepted` |
| `EnsembleSliceKernel` | ensemble | `expansions`, `contractions`, `truncated` |

**Chain vs. ensemble** is an explicit property because it decides what a convergence test may use.
- The walkers of one ensemble are not independent chains, so R-hat across them is no test.
- Diagnostics for an ensemble kernel therefore need several independent ensembles (piece 4). The driver
  refuses to report R-hat over walkers.

### 3. The warm-up, once

- **`WarmupSchedule`:** Stan's windows (init buffer 75, a first slow window of 25 that doubles, term
  buffer 50, and Stan's fallback for short warm-ups), moved out of `MCMCSampler.cpp`.
- **`DualAveragingStepSize`:** Hoffman & Gelman Algorithm 5 with Stan's constants (gamma 0.05, t0 10,
  kappa 0.75). One implementation, used by NUTS and the blocked Metropolis.
- **`CovarianceEstimator`:** a running covariance over a window, regularised as Stan's
  `covar_adaptation`: `(n / (n + 5)) S + 1e-3 (5 / (n + 5)) I`. Used by the blocked Metropolis's proposal
  and NUTS's dense metric (the step PRD-146 needs next).

### 4. `run_sampler`: the driver, and one result type

```cpp
struct SamplerOptions { int warmup = 1000, draws = 1000, thin = 1, chains = 4, threads = 0; std::uint64_t seed = 1;
                        std::function<void(int done, int total)> observer; };
struct SampleResult {
  std::string kernel; std::vector<std::string> names, stat_names;
  // [chain][draw][dim]: a chain kernel's chains, or an ensemble kernel's independent ensembles x walkers
  std::vector<std::vector<std::vector<double>>> draws;
  std::vector<std::vector<double>> log_density;
  std::vector<std::vector<std::vector<double>>> stats;     // [chain][draw][stat]
  std::vector<int> independent_group;                      // which chains are independent of each other
  long evaluations; double seconds;
  std::vector<std::string> warnings;                       // e.g. slice truncations, warm-up divergences
};
SampleResult run_sampler(const SamplingTarget&, const SamplerKernel& prototype,
                         const std::vector<std::vector<std::vector<double>>>& starts, const SamplerOptions&);
```

- **Parallelism:** independent chains or ensembles run on threads (`internal/BayesianParallel.h`'s pool).
- **Seeds:** split from one base seed, as `trajectory_seeds` does.

### 5. `SamplerDiagnostics.h`: the convergence analysis

- **Contents:** tttrlib's `McmcDiagnostics.h` moves here unchanged in method, into `IMP::bff`: rank
  R-hat, bulk/tail ESS, MCSE, following Vehtari et al. 2021, checked against arviz.
- **Summaries:** `convergence(const SampleResult&, summary)` gives mean, sd, MCSE, R-hat, bulk/tail
  ESS and tau for any scalar function of a draw.
- **Independence:** only chains in different `independent_group`s count as independent for R-hat.
- **Declared thresholds:** `SamplerVerdict` holds thresholds declared before the run (R-hat, ESS, zero
  post-warm-up divergences, zero slice truncations) and returns pass/fail with the reasons, so Rule 0 is
  code, not prose.

### `MCMCSampler` stays, as a facade

- **API unchanged:** its public API and SWIG wrapping do not change, so chisurf's `sampler_bff.py` keeps
  working.
- **Inside:** it builds a `SamplingTarget` from its ports or function and a kernel from its algorithm
  string, then keeps the chain in its flat (step, walker) layout.
- **New:** a fifth algorithm, `"nuts"`, and `set_objective_function_with_gradient`.

## Steps, each with its check

Every step is committed separately and is green before the next starts. Byte-for-byte reproducibility
under a fixed seed is kept within a version (`test_sampler.py`). Seeded chains are **not** promised to
be identical across this refactor; the contract is statistical, as `MCMCSampler.h` already states.

1. **Diagnostics into bff.** `include/SamplerDiagnostics.h` from tttrlib's `McmcDiagnostics.h`, with the
   tttrlib C++ test ported to `test/sampler/` and `test/decay/test_mcmc_diagnostics.py` pointed at it.
   - *Done when* the arviz comparison passes on all seven sets at its current tolerances, and
     `BayesianDecaySampling.h` no longer includes a vendored header.
2. **Target, kernel interface, driver, `NutsKernel`.**
   - `NoUTurnSampler` becomes `NutsKernel`, with the fixed end momenta.
   - tttrlib's test is ported: the analytic checks, and the tree-depth histogram against Stan.
   - *Done when:*
     - the ported tests pass;
     - the depth check fails with the old bug re-injected (run once, recorded);
     - the ucfret `nuts_vs_stan` benchmark, rebuilt on bff's header, again passes PRD-146 B1 on g20,
       poisson and schools and B2 on the funnel.
3. **The warm-up, once.**
   - `WarmupSchedule`, `DualAveragingStepSize` and `CovarianceEstimator`, with unit tests: the window
     boundaries against Stan's for warm-ups of 20, 150, 1000 and 5000; the dual-averaging sequence
     against a transcription of Stan's `stepsize_adaptation::learn_stepsize` on a fixed input stream at
     1e-15; the regularised covariance at 1e-14.
   - `MCMCSampler`'s blocked Metropolis switches to them.
   - *Done when* `test/sampler/test_sampler.py` passes unchanged and `bench_sampler.py` runs within 10 % of
     its time before the change.
4. **The four existing algorithms become kernels; `MCMCSampler` becomes the facade.**
   - *Done when:*
     - `test/sampler/test_sampler.py` passes unchanged;
     - chisurf's sampler tests pass against the rebuilt module (run, not edited: chisurf is read-only);
     - on the 20-d Gaussian each algorithm's means and variances are within 4 MCSE of the truth, over
       independent groups.
5. **The decay sampler on the interface.**
   - `bayesian_decay_nuts_chain` and `bayesian_convergence` are replaced by `run_sampler` +
     `bayesian_decay_sampling_target` + `convergence`; the duplicates are deleted.
   - *Done when* `test/decay/test_bayesian_decay_nuts.py` passes, with its strict xfail unchanged.
6. **tttrlib cleanup.**
   - Remove `NoUTurnSampler.h`, `McmcDiagnostics.h` and their tests from tttrlib, with a commit naming

   - *Done when* the tttrlib C++ tests that remain build and pass, and no file in tttrlib, bff or
     ucfret includes the old paths (`grep` empty).
7. **Then PRD-146 continues** on this interface: windowed dense metric adaptation in `NutsKernel`,
   benchmarked against Stan's `dense_e` the B1 way, before any CBM56 chain.

## Risks and what is not in this PRD

- **`MCMCSampler.cpp` is chisurf's engine.** Step 4 is the risky step, and it comes after the new
  pieces are proven on NUTS (step 2) and on the warm-up (step 3). If step 4 threatens chisurf's
  behaviour, the facade may stay on the old internals, with only NUTS and the warm-up shared. That is
  recorded as a decision, not done quietly.
- **Speed:** `std::function` per evaluation costs nanoseconds, against micro- to milliseconds per
  log density. The ensemble kernels keep their batch evaluation over walkers.
- **Not here:** constrained-to-unconstrained transforms for NUTS on bounded graph targets (the decay
  posterior is already unconstrained); a Python/SWIG surface for `run_sampler`; tempering; the HMM
  sampler in tttrlib, which is a Gibbs scheme specific to HMMs and stays.

## Amendment A1 (2026-09-15 17:00, tpeulen, ucfret prompt 468): the sampler publishes its methods

tpeulen: "does the sampler promote the methods, so that chisurf can pick up what is possible?"

**As first written, no.** Today chisurf hand-maintains what bff can do:
- `chisurf/core/fitting/sample.py`'s `SAMPLERS` table holds names, labels and descriptions.
- `sampler_bff.py`'s `_default_n_adapt` copies the C++ warm-up defaults (its comment: "mirroring the
  C++ side's own per-algorithm defaults").

A kernel added in bff is therefore invisible to chisurf until someone edits Python, and a changed default
drifts silently. The fix is the `GraphNodeRegistry` pattern: bff declares, and callers read.

### `SamplerRegistry` and `SamplerDescriptor`

```cpp
struct SamplerOption {
  std::string name, type;              // "int" | "double" | "bool" | "string" | "matrix"
  std::string default_json, doc;       // the default as JSON; one-sentence doc
  double min = NaN, max = NaN;         // NaN = unbounded
  std::vector<std::string> choices;    // for "string"
  bool adapted_in_warmup = false;      // e.g. NUTS step_size: a start value, tuned during warm-up
};
struct SamplerDescriptor {
  std::string name, label, description, citation;
  std::vector<std::string> aliases;
  std::string kind;                    // "chain" | "ensemble"
  bool requires_gradient = false;
  bool uses_covariance_seed = false;   // accepts a curvature / Laplace covariance
  bool uses_blocks = false;            // uses an InferenceFactorGraph's blocks
  bool supports_bounds = true;         // NUTS: false (needs an unconstrained target)
  std::vector<SamplerOption> options;
  std::vector<std::pair<std::string, std::string>> statistics;   // per-draw stat name, doc
  std::vector<std::string> required_checks;                      // e.g. "divergent == 0 after warm-up"
};
class SamplerRegistry {
 public:
  static void register_kernel(const SamplerDescriptor&, std::function<std::unique_ptr<SamplerKernel>(const std::string& options_json)>);
  static std::vector<std::string> get_registered_kernels();              // sorted
  static SamplerDescriptor describe(const std::string& name_or_alias);   // throws, listing what exists
  static std::string catalog_json();                                     // every descriptor, one JSON document
  static int default_warmup(const std::string& name, int n_draws);       // replaces the mirrored defaults
  //! which kernels can run this target, each refusal with its reason ("needs a gradient; the objective has none")
  static std::string applicable_json(const SamplingCapabilities&);
  static std::unique_ptr<SamplerKernel> create(const std::string& name, const std::string& options_json = "{}");
};
struct SamplingCapabilities { std::size_t dim; bool has_gradient, has_bounds, has_covariance_seed, has_blocks; };
```

**Where it surfaces:**
- `MCMCSampler` gets static `get_algorithms()`, `get_catalog_json()`, `get_default_warmup(name, n)`,
  and `get_applicable_json()` for its configured objective. They are wrapped in SWIG, so the catalogue
  costs one crossing at begin, per chisurf's boundary contract.
- `set_algorithm` accepts every registered name and alias. `set_options_json` sets any declared option,
  and rejects undeclared names and out-of-range values with the option's doc in the message.

**The JSON shape** matches what chisurf's `SAMPLERS` already carries (`label`, `description`), plus the
option list with types, defaults, bounds and docs. That is what an AutoForm method declaration needs to
render a form without anyone writing one. chisurf is read-only to this work: bff provides the catalogue;
switching `SAMPLERS` and `_default_n_adapt` to read it is chisurf's change to make.

**Honesty fields are part of the contract.**
- `requires_gradient`, `supports_bounds`, `kind` and `required_checks` are published, so a GUI cannot
  offer NUTS on a gradient-free graph, or report R-hat over the walkers of a single ensemble, without
  the catalogue having said it must not.

### Step 2b (after step 2; the other four kernels register in step 4)

*Done when:*
- `catalog_json()` validates against a JSON schema in `test/sampler/`;
- every registered kernel is constructible from its declared defaults alone, and each declared option
  set through `options_json` is read back from the kernel;
- an undeclared option and an out-of-range value are both refused;
- `applicable_json` refuses NUTS for a target without a gradient, with the reason;
- `default_warmup` equals the values chisurf's `_default_n_adapt` hard-codes today, for stretch, DE and
