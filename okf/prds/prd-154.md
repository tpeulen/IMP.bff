# PRD-154: Native clean-room Nano-Positioning System (NPS) inference

**Status:** active (2026-09-28).

**Goal:** Reimplement the scientifically defined Fast-NPS inference target as a native, testable `IMP.bff` model, while reusing BFF FRET physics and existing IMP/BFF sampling facilities where their state-ownership semantics are appropriate, rather than importing the upstream MATLAB/MEX implementation.[1][2][3]

**Done:** The Fast-NPS distribution is staged in `junk/Fast-NPS-CPC-2017/` solely as a behavioral reference. Clean-room BFF C++/SWIG tracers implement the five dye-model flag combinations, direct non-convolved FRET efficiency, direct transfer anisotropy, and a generic normalized scalar Gaussian log density. They passed their focused build, Python, CTest, public-API, specification, and code-quality gates.[1][2]

**Missing:** A safe bridge from live existing IMP structural/label-site state into a Bayesian NPS direct-observation posterior; legacy convolution compatibility; complete AV/cloud FRET composition; multi-observation semantics; and a BFF photon-network composition layer.

**Next:** Implement a test-first `bff_structural_direct` posterior tracer: a thin BFF restraint reads two existing live IMP label-site `XYZ` coordinates; two explicitly named nuisance particles are sampled under proper priors with one IMP Monte Carlo transaction. This does not claim Fast-NPS sampler or AV-cloud parity.

## Clean-room boundary

- Production source must be authored natively in `include/`, `src/`, and `pyext/`; it must not include, compile, translate, or copy upstream MATLAB/MEX/C++ implementation text.
- `junk/Fast-NPS-CPC-2017/` is a behavioral fixture source, not a build input.
- This work does not depend on a licence determination because no upstream implementation is adopted. The scientific/behavioral source remains traceable through the official NPS page, distribution, and method/software records.[1][2][3]
- Native BFF behavior that intentionally differs from the Fast-NPS compatibility specification must be named and versioned as such; it may not be presented as parity.

## Scope and staged model contract

### S0 — public model identity

A dye model is an explicit value type, not a GUI integer whose semantics are inferred downstream.[2][3]

| `index` | `fixed_mean_position` | `isotropic` | `distance_convolved` |
|---:|:---:|:---:|:---:|
| 1 | false | false | false |
| 2 | false | true | false |
| 3 | true | true | true |
| 4 | false | true | true |
| 5 | false | false | true |

Invalid model indices must raise a BFF/IMP domain exception.[unverified] `modelInd` is metadata only; the compatibility likelihood behavior is determined by the explicit flags.[2][3]

### S1 — direct single-configuration compatibility likelihood

#### S1a — direct non-convolved FRET-efficiency tracer (completed)

The next public primitive is intentionally narrower than a likelihood:

\[
\operatorname{nps\_direct\_fret\_efficiency}(d_1,d_2,R_{\rm iso})
\longrightarrow \hat E.
\]

Each direct dye state stores \((x,y,z,m,\phi,r_{\rm avg})\), with coordinates and \(R_{\rm iso}\) in Å and \(\phi\) in radians. The native function derives \(q=\sqrt{r_{\rm avg}/0.4}\) itself, rather than accepting a caller-supplied \(q\), so the public surface cannot silently skip the Fast-NPS anisotropy conversion.[2][3]

It evaluates only the non-distance-convolved direct branch, returning efficiency alone. It must not interpret `isotropic` or `fixed_mean_position` metadata, expose coefficient rows, evaluate transfer anisotropy, consume observations/errors, construct a likelihood, or create a posterior/sampler. A later dispatcher may use `distance_convolved` metadata to select the separately specified convolution mode.

For valid inputs, this tracer uses BFF's `wobbling_kappa2(delta, q_1, q_2, beta_1, beta_2)` after reconstructing the NPS unit dipoles and geometry; its expression is algebraically identical to the direct compatibility orientation factor below. The NPS layer retains responsibility for state convention, validation, and the 150 Å cutoff.

A valid geometry can have exact \(\bar\kappa^2=0\). The native evaluator must map a nonpositive floating-point result from the orientation primitive to exact \(\hat E=0\), preventing cancellation-scale negative efficiencies; an unexpected non-finite orientation result is an error rather than an observable.[unverified]

The native valid-input contract is finite coordinates, finite \(\phi\), \(m\in[-1,1]\), \(r_{\rm avg}\in[0,0.4]\), finite \(R_{\rm iso}>0\), and strictly nonzero dye separation.[unverified] Validate every field and the derived separation before applying the far-distance cutoff; malformed far-apart input, including finite endpoint coordinates whose subtraction overflows, must raise rather than silently return zero. The upper anisotropy bound is an intentional BFF invalid-input tightening, derived from the fixed fundamental-anisotropy convention, not a claim of permissive legacy parity.[unverified]

A dye state follows the Fast-NPS parameter convention.[2][3]

\[
d_i=(x_i,y_i,z_i,m_i,\phi_i,r_{{\rm avg},i}),\qquad m_i=-\cos\theta_i.
\]

Define \(c_i=-m_i\) and the unit transition-dipole representative:

\[
\mathbf u_i=(\sqrt{1-c_i^2}\cos\phi_i,
             \sqrt{1-c_i^2}\sin\phi_i,
             c_i).
\]

For \(\mathbf r=\mathbf p_2-\mathbf p_1\), \(r=\|\mathbf r\|\), and \(\hat{\mathbf r}=\mathbf r/r\), define:

\[
c_T=\mathbf u_1\cdot\mathbf u_2,\quad
c_1=\hat{\mathbf r}\cdot\mathbf u_1,\quad
c_2=\hat{\mathbf r}\cdot\mathbf u_2.
\]

Fast-NPS derives the compatibility order/depolarization parameter from steady-state anisotropy.[2][3]

\[
q_i=\sqrt{r_{\mathrm{avg},i}/0.4}.
\]

Fast-NPS uses the following direct compatibility orientation factor.[2][3]

\[
\bar\kappa^2=(c_T-3c_1c_2)^2q_1q_2
+\frac{2-q_1-q_2}{3}
+c_1^2q_1(1-q_2)
+c_2^2q_2(1-q_1).
\]

With \(R_{\mathrm{iso}}\) defined at the isotropic \(\kappa^2=2/3\) convention, Fast-NPS maps that factor to an efficiency as follows.[2][3]

\[
\bar R_0^6=1.5R_{\mathrm{iso}}^6\bar\kappa^2,
\qquad
\hat E=\frac{\bar R_0^6}{\bar R_0^6+r^6}.
\]

For direct Fast-NPS compatibility, the predicted efficiency is exactly zero only when \(r>150\) Å; the point \(r=150\) Å remains evaluated.[2][3]

Fast-NPS specifies the following transfer-anisotropy prediction.[2][3] It is the order-parameter form of the experimentally derived relation for the anisotropy of transferred excitation.[6]

\[
\hat r_T=q_1q_2\frac{3c_T^2-1}{5}.
\]

For the isolated S1b native tracer, `nps_direct_transfer_anisotropy(dye1, dye2)` evaluates only this equation. It retains the public `NPSDirectDye` finite/range validation but deliberately has no separation, \(R_{\rm iso}\), 150 Å cutoff, model flag, or activity flag; finite coincident positions are valid because the equation depends only on transition-axis orientations.[unverified] Valid direct values lie in \([-0.2,0.4]\); a rigid aligned pair gives \(0.4\), a rigid orthogonal pair gives \(-0.2\), and either zero-anisotropy dye gives zero.[6]

Each active observable is conditionally independent with normalized Gaussian log likelihood.[2][3]

\[
\ell(y,\hat y,\sigma)=-\tfrac12\left(\frac{y-\hat y}{\sigma}\right)^2
-\log\sigma-\tfrac12\log(2\pi).
\]

The S1b scalar implementation is the generic BFF primitive `normal_log_density(value, loc, scale)`, not an NPS-prefixed duplicate: it validates finite inputs and strictly positive finite `scale`, includes the normalization above, and permits a finite-but-extreme residual to evaluate to `-inf` rather than NaN.[unverified] Its generic surface intentionally does not restrict a caller's observation to the physical transfer-anisotropy range.

The full S1 likelihood is the sum of active FRET and transfer-anisotropy contributions. This is the compatibility surface encoded by the Fast-NPS distribution/software record.[2][3]

The reference sampler's retained-setting construction drops a transfer-anisotropy-only measurement before likelihood evaluation, despite raw/GUI-level independent activity flags; its combined FRET-plus-TA behavior is also not determinate for every non-direct FRET branch. Those flag/dispatcher policies are deliberately deferred: the S1b scalar primitives take no activity flags and own no summation rule.[2][3][unverified]

The NPS experimental framework and treatment of fluorescence constraints are described in the associated methodological literature.[4][5]

**Required native input validation:** finite state coordinates/angles; \(m\in[-1,1]\); finite \(\phi\); \(R_{\mathrm{iso}}>0\); each active uncertainty \(\sigma>0\); and a defined nonzero separation for an oriented direct calculation.[unverified] Errors must be clear exceptions, never silent NaNs or out-of-bounds memory access.[unverified]

### S2 — IMP-owned Bayesian structural direct-FRET tracer

#### Ownership and transaction boundary

The first Bayesian structural tracer is **not** a `GraphPort`/`MCMCSampler` posterior. Its posterior state is one existing `IMP::Model`: hierarchy, `XYZ` coordinates, rigid bodies, existing point label sites, existing AV particles when explicitly supplied, structural restraints, and nuisance particles all live there. One `IMP::core::MonteCarlo` is the sole proposal, acceptance, rejection, and rollback transaction owner. This avoids a hybrid in which GraphPort trials mutate an IMP rigid body without an IMP rollback guarantee or cache invalidation for out-of-band IMP motions.

The new BFF component is a thin `NPSIsotropicFRETEfficiencyRestraint`. It reads two current existing `XYZ` endpoint particles during each score, creates stack-local `NPSDirectDye` values only for the direct-function call, and owns no independent coordinate, label, hierarchy, AV, graph-port, sampler, or prior representation. The first deterministic test uses two actual point/`ATOM` sites. An AV mean-position particle may later be passed only as an explicitly documented fixed-shape mean-position approximation, never as an assertion of AV/cloud FRET equivalence.[4][5]

#### Observation model and sampled nuisance coordinates

The tracer uses model-2 isotropic direct NPS semantics: both temporary dyes have \(m=0\), \(\phi=0\), and \(r_{\rm avg}=0\), so the direct efficiency is the isotropic \(\bar\kappa^2=2/3\) branch of the already specified Fast-NPS forward equation.[2][3] Let \(X\) denote the existing IMP structural state and define the positive physical Förster radius through a dimensionless nuisance coordinate:

\[
\eta_R=\log\!\left(R_{\rm iso}/1\,{\rm \AA}\right),
\qquad R_{\rm iso}=\exp(\eta_R)\,{\rm \AA}.
\]

For one calibrated raw FRET-efficiency observation, the explicitly declared local model is

\[
E_{\rm obs}\sim
\mathcal N\!\left(
  \hat E_{\rm NPS}(X,\exp(\eta_R))+b_E,\;\sigma_E^2
\right),
\]

with proper priors on the two sampled `IMP::isd::Nuisance` coordinates:

\[
b_E\sim\mathcal N(0,\tau_b^2),
\qquad
\eta_R\sim\mathcal N\!\left(
  \log(R_{\rm iso,cal}/1\,{\rm \AA}),\tau_R^2
\right).
\]

The Gaussian prior on \(\eta_R\) induces a lognormal prior on physical \(R_{\rm iso}\) under the stated one-Å reference unit. The likelihood is the normalized raw-scale Gaussian already defined above.[2][3] It is intentionally not clipped to `[0,1]`; values outside that interval are permitted by this local approximation. A bounded/logit/Beta observation model is a separate future specification, not an implicit behavior of this tracer.

The negative-log posterior score at `kT=1` is

\[
\begin{aligned}
S(X,b_E,\eta_R)=&\;S_{\rm struct}(X)\\
&-\log\mathcal N\!\left(E_{\rm obs};
 \hat E_{\rm NPS}(X,\exp(\eta_R))+b_E,\sigma_E\right)\\
&-\log\mathcal N(b_E;0,\tau_b)\\
&-\log\mathcal N\!\left(\eta_R;
 \log(R_{\rm iso,cal}/1\,{\rm \AA}),\tau_R\right).
\end{aligned}
\]

`S_struct` must be a dimensionless negative-log structural prior calibrated to the same `kT=1` convention, not an arbitrary force-field or kcal/mol-like score mixed without a stated temperature/energy conversion. The FRET term alone is not a proper positional posterior, particularly because the direct compatibility leaf returns exactly zero efficiency past 150 Å. One FRET datum cannot identify structure, additive bias, and Förster-radius calibration without these informative priors and/or additional independent observations. Therefore synthetic test widths (for example `0.02`, `0.05`, and `0.1`) are regression pins only, never scientific defaults.

#### Sampler and derivative policy

The first sampler uses one `IMP::core::RigidBodyMover` per movable existing rigid body and one `IMP::core::NormalMover` each for \(b_E\) and \(\eta_R\). The prior terms use existing normalized `IMP::isd::GaussianRestraint` objects. `NPSIsotropicFRETEfficiencyRestraint` is MC-only in S2 and rejects derivative accumulation: no minimization, NUTS, analytic-gradient, replica-exchange, or tempering claim is made until corresponding derivatives and state semantics are independently specified and tested.

`MCMCSampler` and `GraphPort` remain reusable BFF facilities for a later pure graph/vector posterior or read-only diagnostics, but may not sample any state shared with this IMP posterior until cache invalidation and accept/reject synchronization are explicitly designed and tested.

### S3 — two deliberate scientific modes

1. **`fast_nps_legacy` compatibility mode:** preserves this PRD's direct likelihood, cutoff, parameter convention, and later the optional polynomial distance-convolution surrogate.[2][3]
2. **`bff_structural_direct` native tracer:** reads live existing IMP label-site `XYZ` state through the S2 restraint and samples explicit nuisance coordinates under priors. Its initial point/mean-position representation is not AV/cloud FRET and does not claim historical sampler or convolution parity.
3. **`bff_physical_av` native mode:** a later complete model evaluates existing BFF dye clouds/accessibility volumes with the corresponding FRET/orientation machinery and explicitly specified AV rebuilding/caching semantics. It is a different posterior from Fast-NPS's uniform-20-Å-sphere convolution surrogate and must not claim historical parity.[2][3][4][5]

### S4 — BFF photon-network composition

A later `FRETNetworkNPSModel` composes `FRETNetworkModel` rather than inheriting from or modifying its private parameter bookkeeping.[unverified]

- outer variables: state-specific 3-D label positions and position priors;
- derived inner means: pair distances \(\|x_{s,a}-x_{s,b}\|\);
- reused inner machinery: hidden-process photon likelihood, emission/process handling, and likelihood gradients;
- outer gradient: Euclidean chain rule from pair-distance derivatives to label coordinates;
- first release: discrete hidden processes only; reject landscape coordinate functions until their semantics are separately specified.

## Non-goals for the first vertical slice

- Implicit conversion of BCP weights into a density prior.

## Phase 2 addendum — network likelihood core (2026-09-29)

The multi-dye dynamic-regime likelihood of Fast-NPS `logLikelihood.cpp` is now
native in `IMP.bff`: `nps_network_fret_efficiency`,
`nps_network_transfer_anisotropy`, `nps_network_log_likelihood` (+ `NPSNetworkDye`,
`NPSMeasurement` value types). Zero physics duplication: FRET reuses the
committed `wobbling_kappa2` route, the likelihood accumulates via the committed
`normal_log_density`, and Fast-NPS's five copies of the 12-term polynomial
collapse into one Horner evaluator. Orientation grid: 5 azimuthal x 5 polar
slots per dye (row = 5*phi_slot + polar_slot, azimuth scale literal 5/3.142),
clamped at the domain edges (the reference's raw cast would index row 25 of a
25-row table at phi = pi).

Peak verification vs the Fast-NPS oracle: 120 random 4-dye/3-observation
networks, max |logL difference| = 1.4e-13 (float noise); scalar direct-FRET
route identical to 3.3e-16 over 300 configurations. Verification suite:
`test/nps/test_nps_network.py`, 32 tests, green with the full battery (267
focused tests + CTest 3/3). Executed example notebook: `ipynb/example/nps.ipynb`.

Deferred by design: AV convolution/resampling samplers, multi-observation
dispatchers, replica-exchange sampling, derivatives/NUTS, checkpoint
serialization.
