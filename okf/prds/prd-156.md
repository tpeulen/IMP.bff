## What is there today (checked at 6204fa8d2)

* `InferenceFactorGraph::to_json/from_json/save/load` round-trip the **structure** exactly. Scores
  (`InferenceFactorScore`, the numbers of a factor) are carried by copies but not written; a loaded
  graph cannot be evaluated.
* `inference_fitting(graph, theta0, max_iterations, tolerance, line_search_below)` fits every
  coordinate. There is no way to hold a coordinate fixed, so a hyperparameter (the P-spline weight
  lambda) cannot be held while the rest is fitted, and the Laplace evidence is always over all
  coordinates.
* `include/bayesian/BayesianDecayPosterior.h` (1062 lines, header-only) mixes three things:
  1. **the model** -- `bayesian_decay_log_prior`, `_log_likelihood`, `_evaluate`,
     `_log_posterior_and_gradient`, `_weighted_sum`, `_distribution_with_sd`. The factor graph's
     scores (`src/bayesian/BayesianDecayFactorGraph.cpp`) call these.
  2. **generic algorithms written for one model** -- `_laplace_evidence`, `_covariance`, `_hessian`
     (finite differences of the gradient), `_polish_exact`, `_laplace_evidence_exact`, the tilt
     (`_mean_rel_tilt`, `_fit_node_tilted`) and Tierney-Kadane (`_tk_mean_rel`).
  3. **loops and recipes** -- `bayesian_decay_fit_node` (now `inference_fitting`),
     `bayesian_decay_declared_starts` (data start + three Adam phases tuned on CBM56),
     `bayesian_decay_fit_best_of_starts`, `bayesian_decay_fit_lambda_grid` (+ options, node and grid
     types).
  `BayesianDecaySampling.h` wraps (1) as a `SamplingTarget`.
* lambda is already a variable when free (`log10_lam`, logit on [lo, hi]) or a held value
  (`fixed_values`); the prior reads either (PRD-143 A4.6).
* ucfret's add-on uses only `bayesian_decay_factor_graph`, `inference_fitting`,
  `bayesian_decay_distribution_at`, `bayesian_decay_distance_grid` (grep, 2026-11-11). Users of (2)
  and (3): 13 files in `test/decay/`, the CBM56 examples in `examples/spectroscopy/bayesian_decays/`,
  and ucfret's investigation programs `investigation/pinn_pR_anisotropy/s89_cpp/*.cpp` (records,
  pinned to older bff commits).

## The design

**bff provides the graph, its evaluation, one fitting, the curvature and evidence at a point, and
serialisation. Anything that repeats a fit -- restarts, several starts, a hyperparameter grid, a
schedule -- is a loop the user writes.**

### D1. Hyperparameters are ordinary graph variables

No new concept. A hyperparameter is a variable of the graph (role `"hyper"` by convention; its
hyperprior a factor of kind `INFERENCE_FACTOR_HYPER`, which exists). What it needs is that a fit can
hold any variable:

```
inference_fitting(graph, theta0, max_iterations, tolerance, line_search_below,
                  fixed = [])        # variable keys held at their theta0 values
```

With `fixed`, the Newton steps and the Laplace evidence run over the free coordinates only, so
`laplace_evidence` with lambda held **is** log p(y | lambda) -- the number the lambda grid weights by.
A sampler, which does not maximise, may take lambda free. Why lambda must not simply be maximised
with the rest: p(c | lambda) grows as lambda^{rank/2} towards the penalty's null space, and the joint
mode runs to large lambda (CBM56: log10 lambda 3.9, against 40 % of the evidence at -1; PRD-143 A4.6).

### D2. Save and load, with optional embedded data (msgpack)

```
graph.save(path, embed_data=False)      # default: JSON structure, as today (byte-identical)
graph.save(path, embed_data=True)       # msgpack document: structure + every score's data
graph.load(path)                        # detects the format; with data, the graph is evaluable
graph.to_msgpack(embed_data) -> bytes; graph.from_msgpack(bytes)
```

* A score that can be written says so: `InferenceFactorScore::get_score_type()` (default `""`, not
  writable) and `get_score_document()` (a JSON tree whose arrays are msgpack `bin`, float64
  little-endian with a shape). Rebuilding from a document goes through **bff's one registry**
  (capability `"factor_score"`, `register_algorithm_json`), as samplers do -- no second mechanism.
* Scores that share data (the decay graph's `counts`, `prior` and `observation:*` share one
  experiment) write it once: the document stores data blocks by content, scores refer to a block.
* `embed_data=True` with a score that cannot be written (a Python director, a closure) **refuses**
  and names the factor. Nothing is dropped silently.
* Encoding/decoding via `internal/NetworkDocument.h` (`document_to_msgpack` /
  `document_from_msgpack`), the one msgpack path bff already has.
* The theta a graph was last fitted at is not graph state; a user stores it beside the file.

### D3. The Bayesian decay posterior made generic

| Today (`BayesianDecayPosterior.h`) | After |
|---|---|
| model terms (prior, likelihood, expected counts, weighted sum, p(R) and its sd) | private to `src/bayesian/` (an `internal/` header), used only by the decay graph's scores; no public `bayesian_decay_*` posterior API |
| `bayesian_decay_laplace_evidence`, `_covariance` | `InferenceFit` already carries the evidence; `inference_covariance(graph, theta, fixed)` |
| `bayesian_decay_hessian`, `_polish_exact`, `_laplace_evidence_exact` | `inference_hessian(graph, theta, fixed)` (central differences of `graph.eval` gradients); `inference_fitting(..., curvature="information"|"hessian")` |
| tilt + Tierney-Kadane (`_mean_rel_tilt`, `_fit_node_tilted`, `_tk_mean_rel`) | a tilt **is a factor**: `log f(theta)` added to a copy of the graph; `inference_tierney_kadane(graph, theta, functional_factor)` returns mean and sd of a positive functional (existing `bayesian_tierney_kadane` underneath) |
| `bayesian_decay_sampling_target` | `inference_sampling_target(graph, fixed)` -- any graph to the sampler interface |
| `bayesian_decay_fit_node` | removed (`inference_fitting`, bit-identical per PRD-155) |
| declared starts, best-of-starts, lambda grid (+ types, options) | removed from bff; loops in user code (ucfret: H7(b)-(d), E4) |

`BayesianLaplace.h` (`BayesianEvidenceMixture`, `bayesian_tierney_kadane`) is already generic and stays.

## Steps (each: done when)

1. **This PRD**, committed alone. Done when: committed; ucfret's `okf/questions-tpeulen.md` F1/F2
   point here.
2. **Fixed variables in `inference_fitting`** (D1). Done when: `fixed=[]` is bit-identical to today
   (theta, log posterior, evidence, iterations on the decay fixture); on a Gaussian toy graph with
   one coordinate held, mode and evidence equal the closed form of the conditional to 1e-10; on the
   decay fixture with `log10_lam` held at the grid's node values, the evidence equals
   `bayesian_decay_fit_lambda_grid`'s node evidence (same start, same tolerance) to 1e-8 nats -- a
   control at a different lambda must differ.
3. **Save/load with embedded data** (D2). Done when: `embed_data=False` writes the bytes of today;
   decay graph with three observations saved with data, loaded in a fresh process, `eval` and
   `inference_fitting` equal the original bit for bit; a graph with a Python-director score refuses
   `embed_data=True` naming the factor; a corrupted document (truncated, wrong block reference) is
   refused, not half-loaded; an unknown score type is refused naming the type.
4. **Generic curvature, covariance, TK and sampling target** (D3, middle rows). Done when: each
   equals the decay-specific function it replaces on the decay fixture (Hessian and covariance to
   1e-10 relative, exact-curvature evidence and TK mean/sd to 1e-8) -- parity tests written while the
   old code still exists, so the comparison can fail.
5. **Remove the decay-specific public API** (D3, last rows): model terms to `internal/`, loops and
   recipes deleted, `BayesianDecaySampling.h` replaced by the generic target. Tests in `test/decay/`
   ported to the graph (parity already shown in steps 2-4) or deleted with the function they tested,
   each listed in the log. Examples that call removed API are listed; those with another session's
   uncommitted edits (`examples/spectroscopy/bayesian_decays/cbm56.py`, 2026-11-11) are not touched
   and are recorded as follow-up. Done when: no public `bayesian_decay_*` symbol beyond
   `bayesian_decay_factor_graph`, `_distribution_at`, `_distance_grid` (and the experiment loader
   the graph needs); decay suite and factorgraph/registry/public-API suites pass on the native wheel.
6. **Wheels** (native cp311/cp312 macOS arm64, Pyodide cp313). Done when: built from the committed
   tree, ucfret's add-on tests pass on the native wheel, the Pyodide graph check
   (`tools/pyodide/bayesian_decay_fitting_check.mjs`) equals native.

## What is not in bff after this, and where it goes (ucfret)

* **Endpoint restart** (ucfret H7(b), F1): `while gain > X and n < N: fit = inference_fitting(graph,
  fit.theta)`; X and N are declared by drieger/tpeulen (proposal: 0.01 nats, 5).
* **Declared starts** (H7(c)/(d), F2): a list of theta vectors (the data start, reference modes from
  the instrument profile), each fitted, all recorded, the best kept.
* **lambda grid** (E4): for each node, hold `log10_lam` (`fixed`), fit, read `laplace_evidence`;
  weight with `BayesianEvidenceMixture`.
* Saving a fit for a later restart: `graph.save(path, embed_data=True)` plus the theta.

## Risks

* Step 5 removes API that ucfret investigation programs (s89_cpp) and the CBM56 examples call. They
  are records pinned to older commits; they are not ported.
* The decay scores share one context built from the experiment directory; embedding must rebuild
  that context once, not once per factor (step 3 tests the shared case).
