## The evaluation: which schemes occur, and whether they factor

Amalgamation builds the joint generator of several discrete variables from one conditional
intensity matrix (CIM) per variable. A variable's rates may depend on the states of its parents.
The one assumption is that **no event changes two variables at once**.

| scheme in the stack | where | factors? |
|---|---|---|
| conformation (n) x emission mode (parallel/perpendicular), `k_nrad` conformational, `k_rad` mode switching given the conformation | chisurf `core/fluorescence/burst/simulate.py` `exchange_matrix_ms`, `photoselection_matrix` (index `2 * state + mode`, transposed by hand) | **yes, exactly** -- the test reproduces both matrices |
| conformation x photophysics (S0/S1/T), S1 decay conditioned on the conformation (PET/PIFE FCS) | input to bff `fcs_bunching_factor` / `fcs_saturated_curve_shape`; chisurf's FCS kinetics model takes any N-state scheme, written by hand | **yes** -- the test reproduces the 6-state dark and excitation matrices, and the bunching curve is identical |
| donor label states x acceptor label states | bff `fret_efficiency_exact_kinetic_pair` (`FRETExchange.cpp`) | **yes, no coupling** -- but the code composes *transition* matrices (Kronecker product); see the note below |
| conformational state x radial diffusion coordinate, diffusion scaled by the state's 1/tau | tttrlib `BurstML.cpp` `kron(taumat, Lmat0) + kron(ratemat0, I)` | **yes** (a parent-conditioned CIM), already built in C++ with a fixed structure; not rewired |
| single-dye photophysics: two_state, rhodamine/oxazine 3-state, Cy5 4-state (isomer + triplet) | chisurf `fcs_saturation_calc/schemes/*.json` | **nothing to factor** -- one variable; Cy5's isomer and triplet both leave S1 |
| excited chromophores A*, B* with transfer both ways (FRET, PDDEM) | bff `PhotophysicsTransferKinetics.h` | **no** -- transfer D*A -> DA* changes two variables in one event, which amalgamation sets to zero |
| one conformational chain (dynamic PDA, 3c-PDA, burst likelihood, `SimKinetics`) | chisurf `core/fitting/kinetics.py`, tttrlib | **nothing to factor** alone; it becomes one variable of a product once blinking or bleaching is added |
| labelled species (FRET pair, donor-only, acceptor-only) | the simulator's padding | a direct sum of blocks, not a product |

So the harvest pays for the product schemes, and those do occur in three places. It does not replace
the energy-transfer kinetics, and the header says so.

## What landed

- `KineticIntensityMatrix`: the CIM over one or more variables with parents; `set_rate`,
  `get_rate`, `set_matrix`/`get_matrix` per parent configuration; `extract` (fix parents);
  `amalgamate` (aGrUM's `CIM.amalgamate`, its four cases); `get_generator`; `get_marginal`.
- `KineticNetwork`: aGrUM's `CTBN`. It has `add_variable`, `add_arc` (cycles allowed; rates set
  before an arc are copied to every parent state), `set_rate` with parent values, and
  `get_generator` (amalgamation in declaration order). It also has `get_state_index`/`get_states`
  and `get_marginal`.
- `kinetic_transient_distribution` (aGrUM's `SimpleInference`: `expm(K t) p0`, Eigen's scaling and
  squaring) and `kinetic_stationary_distribution` (aGrUM has none; it throws when the result is not
  unique).
- Not ported: forward-sampling inference. A Gillespie walk on the amalgamated generator is tttrlib
  `SimKinetics`, after a transpose.

A scheme with two clocks, such as FCS `K_dark + k_exc K_exc` or the simulator's `k_nrad`/`k_rad`,
is two networks over the same variables. Amalgamation is linear in the rates, and a test checks that.

## Conventions, and how they map

| | bff `KineticNetwork` | aGrUM `CIM.toMatrix` | tttrlib `SimSystem`/`SimKinetics` |
|---|---|---|---|
| matrix | `K[target, source]`, columns sum to 0 | `Q[from, to]`, rows sum to 0 | row-major source -> target, diagonal ignored |
| joint index | C-order over declaration order, first variable most significant (`ravel_multi_index`, `kron(K0, I) + kron(I, K1)`) | little-endian over **sorted** names (an `Instantiation` increments its first variable fastest) | whatever the caller built |
| diagonal | derived, never stored | whatever was written (its generator writes -sum) | ignored |

So `K_bff = Q_agrum[perm][:, perm].T`, with `perm` the aGrUM index of each bff state. The A/B test
applies exactly that mapping. A transposed or unpermuted matrix is off by 995 (photophysics) and 2.6
(cyclic scheme), so the test would catch either flip.

## Checks (`test/kinetics/test_kinetic_network.py`, 12 tests)

- **Conventions:**
  - a two-state chain is `[[-a, b], [a, -b]]` and follows the closed form;
  - the joint generator of two independent variables is `kron(Kx, I) + kron(I, Ky)`, and the state
    index is `ravel_multi_index`;
  - an event that changes both variables has rate 0;
  - rates are read under the right parent state.
- **aGrUM semantics:**
  - associativity, with an unresolved parent carried through;
  - `extract` commutes with amalgamation;
  - two clocks add;
  - the refusals.
- **Real schemes by hand:**
  - PET FCS: the 6-state dark and excitation matrices are equal to the hand-written ones (0.0
    difference), and `fcs_bunching_factor` gives the same curve from either (0.0 relative);
  - the smFRET simulator's polarised `k_nrad`/`k_rad` in tttrlib's layout are equal to
    `simulate.py`'s loops (0.0), and the untransposed matrix does not match.
- **Inference:**
  - the stationary distribution satisfies `K p = 0`, and the conformation marginal is
    `k_co/(k_oc + k_co)` to 1e-9;
  - the stiff transient (1e9 Hz decay beside 1e3 Hz exchange) is equal to scipy's `expm` to 2e-16
    at 3 ns, and to the stationary distribution at 50 ms.
- **A/B against aGrUM:** `test/kinetics/agrum_ctbn_reference.py` transcribes
  `CIM.amalgamate`, `toMatrix`, `CTBN.add/addArc`, the randomCIMs diagonal and
  `SimpleInference` without pyagrum, which is installed nowhere. It does not import IMP.bff, per the
  prototyping rule, and cites line numbers. It records `test/kinetics/data/ctbn_agrum_fixture.json`
  for two schemes: conformation x photophysics, and a cyclic A <-> B -> D. Generators agree to 0.0
  and 8.9e-16 (1.1e-16 relative); `SimpleInference` posteriors agree to at most 1.6e-15.

## Open

1. **Adopt it where the scheme is written by hand.** In chisurf `burst/simulate.py`,
   `exchange_matrix_ms` and `photoselection_matrix` would become two networks (conformation x mode),
   taking both transposes out of hand-written code. The chisurf FCS kinetics model could offer
   "add a conformation" through this instead of making the user write a 2N-state matrix. Neither was
   changed here: the files belong to active chisurf sessions.
2. **`fret_efficiency_exact_kinetic_pair` composes transition matrices, not generators.**
   `(P_d (x) P_a - I)/dt = M_d (+) M_a + dt M_d (x) M_a`, with `M = (P - I)/dt` as the single-label
   function defines it. The extra term is the chance that both labels jump within one frame. The
   continuous-time composition of the same two generators is the Kronecker sum, which
   `KineticNetwork` builds. Which one is intended is an owner question. Behaviour is unchanged, and
   the existing test pins the product.
3. **Placement.** The amalgamation is generic, and could be std-only and header-only. Under the
   "simple header-only algorithms go to tttrlib, vendored" rule (PRD-146) it would move to tttrlib as
   soon as a tttrlib consumer wants it, for example to generate `BurstML`'s operator or
   `SimKinetics` schemes. The inference half uses Eigen's `MatrixFunctions` and would stay in bff.
