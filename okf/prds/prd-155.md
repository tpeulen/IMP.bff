# PRD-155: the Bayesian decay fit as a graph node, generic observations of p(R), in both wheels

**Status**: written 2026-11-10, not started. **Next**: step 1.

## Why

ucfret's UCFRET add-on fits with a patch kept in the ucfret repository
(`../ucfret/patches/imp-bff/imp-bff-mean-fret-efficiency-127e1b104-reduced1.patch`).
It adds two one-off mechanisms: an exact mean-FRET-efficiency equality
(`BayesianDecayEfficiency.h`: one spline coordinate eliminated, reduced gradient)
and a dedicated SWIG function `fit_bayesian_decay_experiment` (JSON in, JSON out).
tpeulen declined it on 2026-11-10 (`../ucfret/okf/questions-tpeulen.md`, A1):
*"sounds too specific, check if there is no generic way of implementing. the
ultra specific solutions wont survive long"*; *"there are the bayesian networks
this is how to do it"*; *"graphical model"*. bff takes no PRs: this is bff work.

The general mechanisms exist already:

- `BayesianDecayTilt` / `bayesian_decay_mean_rel_tilt` add a term on a weighted
  sum of p(R) (weights `rel`) with exact gradient and Hessian. The mean FRET
  efficiency is the same object with weights `1/(1 + rel^6)`.
- `InferenceFactorGraph` declares likelihood factors; an external measurement of
  a summary of p(R) is one more likelihood factor on the distribution variable.
- `GraphNode` / `GraphNodeRegistry` / `configure(json)` are the Python surface for
  numerical kernels; results are output ports.

Also decided on 2026-11-10 (same file): the fit returns its log posterior split
into log-likelihood and log-prior (A2); the hard floor of the shifted response
gets a smooth (softplus) alternative (A3).

And: the Bayesian decay headers compile only where pocketfft is on the include
path (`#if __has_include("pocketfft/pocketfft_hdronly.h")`). Neither wheel has it,
so **neither the native nor the Pyodide wheel contains any of this code today**.
tpeulen: *"make sure the imp.bff on pyodide work, wheel."*

## What

1. **pocketfft in the build.** Vendor `pocketfft_hdronly.h` (BSD-3, header only)
   as `thirdparty/pocketfft/`, copied byte for byte from tttrlib's vendored copy
   with its licence and a VENDORING note; put it on the include path of the IMP
   module build and the standalone (wheel) build, native and Pyodide.
2. **Generic observations of p(R).** `BayesianDecayObservation {name, weights,
   value, sigma}` on `BayesianDecayExperiment`, read from an optional manifest
   block `observations` (weights given as an array over the R grid, or by name:
   `fret_efficiency` = `1/(1 + rel^6)`, `rel`). Each adds the Gaussian
   log-likelihood `-(sum_j p_j w_j - value)^2 / (2 sigma^2) - log(sigma sqrt(2 pi))`
   to the log posterior. It enters `bayesian_decay_log_posterior`,
   `bayesian_decay_evaluate` (gradient; Fisher term `grad_f grad_f' / sigma^2`,
   the expected information of a Gaussian observation, consistent with the
   scoring matrix of the counts) and `bayesian_decay_log_posterior_and_gradient`,
   so every fitter, the lambda grid, Laplace and NUTS see it without change. The
   derivative of the weighted sum is the code of `bayesian_decay_mean_rel_tilt`,
   factored out into `bayesian_decay_weighted_sum` with `rel` weights giving the
   tilt exactly as before. No exact equality: it is the `sigma -> 0` limit and is
   not added as a mechanism.
3. **The log posterior split.** `BayesianDecayPoint` carries `loglik`,
   `logprior`, `logobs` beside `logpost` (`logpost = loglik + logprior + logobs`).
4. **Softplus response floor.** `BayesianResponseFloor::softplus`, manifest
   `response_floor: "softplus"`: `s * log(1 + exp(t/s))` with
   `s = softplus_scale * max(response)` (default `softplus_scale = 1e-6`), applied
   where the hard floor is (shifted response and each kernel column), with its
   derivative `sigmoid(t/s)` in the tangents. Default stays `hard`: changing it
   changes every existing result, and that is a separate, declared re-validation.
   The bias it adds outside the pulse (`s ln 2` per bin before renormalisation)
   is stated in the header.
5. **The fit as a graph node.** `BayesianDecayFitNode`, registered as
   `BayesianDecayFit`. `configure(json)`: `experiment` (directory of a manifest),
   `start` (array, else the experiment's prior centres are not guessed: required),
   `max_iterations`, `tolerance`, optional `observations` (added to the
   experiment's own). `evaluate()` runs `bayesian_decay_fit_node`. Output ports:
   `theta`, `expected_counts`, `distance_grid` (R/R0), `probability_mass`,
   `log_posterior`, `log_likelihood`, `log_prior`, `log_observation`,
   `observation_values` (sum p w per observation at the mode), `converged`,
   `iterations`, `laplace_evidence`, and per histogram `poisson_deviance`,
   `degrees_of_freedom`, `runs_test_p`, `weighted_residuals` (through
   `poisson_goodness_of_fit`). Registered in the registry entries next to the
   factory (one registry mechanism).
6. **Both wheels.** Native standalone wheel (CPython) and Pyodide wheel
   (`tools/pyodide/build_wheel.sh`) built from this tree; the node is created and
   evaluated on a synthetic experiment in both (`tools/pyodide/smoke_test.mjs`
   gains the check).

Not in scope: changing the default floor; the exact equality; ucfret's adapter
(ucfret's own PRD, after this one lands).

## Steps and done-when

| step | done when |
|---|---|
| 1 pocketfft | `thirdparty/pocketfft/pocketfft_hdronly.h` identical to tttrlib's (`cmp`); a standalone configure finds it; `test/decay` header-only drivers still pass |
| 2 observations | driver test: analytic gradient and Hessian of the observation term equal central differences (and a 1e-3-perturbed Hessian fails the same check); with `rel` weights `bayesian_decay_weighted_sum` reproduces `bayesian_decay_mean_rel_tilt` bit for bit; a synthetic fit with `sigma` small pulls `sum p w` to `value` within 3 sigma while without the observation it does not (the check can fail); an experiment without `observations` gives byte-identical log posteriors to before |
| 3 split | `logpost == loglik + logprior + logobs` to 1e-12 relative on a fixture |
| 4 softplus | tangent check by central differences across a zero crossing at zero shift (the case the hard floor gets wrong); `hard` default unchanged (existing tests pass) |
| 5 node | Python test: `GraphNodeRegistry.create("BayesianDecayFit")`, configure, evaluate on a synthetic experiment; outputs equal a C++ driver's `bayesian_decay_fit_node` on the same input; fit statistic and runs test reported; an observation changes the answer |
| 6 wheels | native wheel installs in a clean env and passes step 5's test; Pyodide wheel loads under Node and passes the same check |

Each step is its own commit. Local commits only; tpeulen pushes.
