# PRD-155: evaluable factors and one generic fit on the factor graph

**Status**: steps 1-4 done (47512f2f9, d10b87f6f); design of the rest revised
2026-11-10 by tpeulen; **next: step 5, after tpeulen reviews this revision.**

## Revision 2026-11-10 (tpeulen)

The first version of this PRD wrapped the Bayesian decay fit as a graph node
(`BayesianDecayFitNode`, a registered `GraphNode`). It was built, not committed,
and removed. tpeulen, verbatim: *"i still do net get why bayesian decay fit node
is needed."* -- *"the factor graph is general"* -- *"factorgraph and abstraction
should be enough. no need for special classes, if there is need abstraction is
bad. doubt that."*

So: **no model-specific classes.** The factor graph (`InferenceFactorGraph`)
already has the concepts -- variables with size and role, factors with kind
(PRIOR, LIKELIHOOD, HYPER, LINK) and scope. What it lacks is generic: a factor
cannot be evaluated, and nothing fits a graph. Add exactly that, and express the
Bayesian decay model as factors whose evaluators are the functions that exist.

## Why

ucfret's UCFRET add-on fits with a patch kept in the ucfret repository
(`../ucfret/patches/imp-bff/imp-bff-mean-fret-efficiency-127e1b104-reduced1.patch`):
an exact mean-FRET-efficiency equality and a dedicated SWIG function
`fit_bayesian_decay_experiment`. tpeulen declined it on 2026-11-10
(`../ucfret/okf/questions-tpeulen.md`, A1): *"sounds too specific ... the ultra
specific solutions wont survive long"*; *"there are the bayesian networks this is
how to do it"*; *"graphical model"*. bff takes no PRs: this is bff work. Also
decided: the fit reports its log posterior split into log-likelihood and log-prior
(A2); a smooth (softplus) response floor (A3). And the Bayesian decay headers
compiled into neither wheel (no pocketfft); tpeulen: *"make sure the imp.bff on
pyodide work, wheel."*

## Done (steps 1-4)

1. **pocketfft vendored** (`thirdparty/pocketfft/`, byte-identical to tttrlib's),
   private include path of both builds. 47512f2f9. The native standalone wheel
   (cp312, macOS arm64) builds with it (2026-11-10).
2. **Observations of a weighted sum of p(R)** with a sigma (manifest block
   `observations`; `fret_efficiency` / `rel` / explicit weights), entering the log
   posterior, its gradient and the scoring information; `bayesian_decay_weighted_sum`
   factored out of the mean-R/R0 tilt (bit-identical). d10b87f6f.
3. **The split** `logpost = loglik + logprior + logobs` on `BayesianDecayPoint`. d10b87f6f.
4. **Softplus response floor** (`response_floor: "softplus"`, data-fixed scale),
   default unchanged. d10b87f6f.

Tests: `test/decay/test_bayesian_decay_observations.py` (6), decay suite 79 passed.
Under the revision, (2) and (3) become what the decay model's factors evaluate;
`BayesianDecayObservation` is a plain record of the manifest and is removed if the
factor evaluators make it redundant.

## What (revised)

5. **Evaluable factors (generic).** A factor of `InferenceFactorGraph` may carry an
   evaluator: a function of the values of its scope returning its log density and,
   when asked, its gradient and its information (positive semi-definite, the
   matrix scoring uses) over the scope. Set with `set_factor_evaluator(key, fn)`;
   a factor without one stays structural, so every existing graph and query is
   unchanged. Variables gain a position in the flat parameter vector (they have
   `index` already) so the graph maps theta to each factor's scope.
6. **One generic fit of a graph.** `inference_fit_map(graph, theta0, options)`:
   damped Newton (`DampedNewton`, as `bayesian_decay_fit_node` uses) on the sum
   of the factors' log densities, their gradients and information; then the
   Laplace evidence. Reports the log posterior **per factor and per kind**
   (likelihood, prior, hyper), which is A2's split without any model knowing
   about it. Nothing in it knows a model.
7. **The Bayesian decay model as factors, no classes.** One function,
   `bayesian_decay_factor_graph(experiment)`, fills a graph from an experiment:
   variables from the manifest's variables (size, role); a LIKELIHOOD factor per
   histogram -- or, if splitting the joint evaluation per histogram costs
   accuracy or speed, one LIKELIHOOD factor over all histograms (decided by
   measurement in this step, recorded); PRIOR factors; the roughness as a HYPER
   factor; each external observation as a LIKELIHOOD factor on `c`. Evaluators are
   closures over the existing functions.
8. **Python and both wheels.** The graph, its evaluation and `inference_fit_map`
   reachable from Python through the existing `InferenceFactorGraph` binding;
   native and Pyodide wheels built from this tree; the same fit run in both.

Not in scope: ucfret's adapter (its own PRD after this lands); changing the
default floor; an exact equality.
