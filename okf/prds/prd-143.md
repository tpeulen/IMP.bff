## Why

PRD-142 moved ucfret's CBM56 analysis into bff and, in doing so, brought in second
copies of things bff already had; and the model-search work ported ChiSurf's TCSPC and
FRET models into the graph, which now overlap the same analysis from the other side.
Two implementations of one concept drift: a derivative gets fixed in one, a
normalisation in the other, and the two stop agreeing silently.

| concept | copy A | copy B | numerics differ? |
|---|---|---|---|

**The rule for every row**: one implementation. Where the numerics differ, the one
implementation carries both as named modes, and every consumer's tests pass through it;
nothing is deleted until its consumers run on the survivor.

## Amendment A3 (2026-09-15, tpeulen, ucfret prompts 449-450: "is there sth in boost to improve accuracy?" / "do it")

**The ridge projection solves the augmented least-squares problem by Householder QR instead of
the normal equations.** Measured on the CBM56 18b targets against a 50-digit reference (mpmath):
normal equations (numpy LU or Cholesky) 3e-7 in coefficients, 3.9e-12 in decays; Householder QR of
`[B; sqrt(lambda) I]` 3.6e-13 and 7.2e-16 -- the normal equations square the conditioning
(2.7e9), the augmented system does not. Boost.Multiprecision would reach the same by brute force
at 10-100x the cost; not used.

Steps, each with its check:

- **A3.1 tttrlib.** `RidgeProjector` gains a solver choice (`RidgeSolver::cholesky`, the present
  default, unchanged for existing callers; `RidgeSolver::qr`): Householder QR of the augmented
  `(m + n) x n` matrix, factored once, `project` applies `Q^T` and back-substitutes. Test: a design
  with a KNOWN singular value decomposition (orthogonal factors, singular values over eight
  decades), whose ridge solution `V diag(s/(s^2+lambda)) U^T y` is exact to round-off: QR within
  1e-10 of it in coefficients; Cholesky outside 1e-8 on the same problem (the control showing the
  gain is real). Re-vendored into bff, pinned.
- **A3.2 bff.** `bayesian_transfer_projector` uses `RidgeSolver::qr`. Gate (ucfret
  `transfer_gate.cpp`): 18b against the 50-digit reference, coefficients < 1e-10 and decays
  < 1e-13; the normal-equation solve must fail that gate (negative control).
- **A3.3 ucfret Python.** `s79._ridge` solves by QR when `MAP_SOLVER == 'ridgeqr'`;
  `cbm56.environment(maps='exact')` selects it, which changes the cache tag, so maps built by the
  normal equations are never reused silently. The CBM56 environment caches are rebuilt; 18c/18d
  are then gated C++ QR against Python QR at the tolerances the 18b result supports (measured,
  recorded). The frozen v17 fit record keeps the tensors it was fitted with (normal equations;
  they differ by ~3e-7 in coefficients, ~4e-12 in decays) -- it is not refitted.
- **A3.4** the B4 coefficient tolerance for C++-built tensors on the frozen fixture stays 1e-6
  (the fixture's tensors are the normal-equation ones); for a fixture emitted from the rebuilt
  environment it tightens to what is measured.

## Steps

1. **The Bayesian headers onto bff's own blocks** (owner: this PRD's author). The decay
   posterior uses `BayesianPSplinePrior`, the transforms (the sum-to-zero basis supplied
   as `Q`), `bayesian_poisson_score` -- extended with optional per-block column lists so
   the live-column sparsity lives in the one function --, `bayesian_log_det_spd` /
   `bayesian_laplace_log_evidence` and `bayesian_delta_variance`; one soft floor with an
   optional threshold. *Done when*: the six copies are gone (a grep in a test), ucfret's
   CBM56 gates pass unchanged (1e-12 against the torch prototype, fit on the polished
   mode), the s89 simulated regression passes, bff's decay tests pass.
2. **Excitation / emission crosstalk once** (owner: the PDDEM port). A header-only kernel:
   excitation [fluorophore x pulse], emission/detection [fluorophore x detector], transfer
   both ways, the map from species decays to channel amplitudes, analytic derivatives;
   the graph node wraps it, `BayesianDecayModel` calls it. *Done when*: no crosstalk
   arithmetic left in `BayesianDecayModel.h`; CBM56 parity and the PDDEM tests pass.
3. **IRF preparation once**: one preparation with modes (ChiSurf's; soft background +
   clamped Fourier shift), used by `TCSPCDecay`, `Convolution` and the decay model.
   *Done when*: one of the two headers is gone; ChiSurf parity tests and CBM56 parity pass.
4. **Convolution once**: the exact bin-integrated periodic kernel as a mode beside the
   recursion (or the reverse), one kernel module. Same done-when.
5. **Polarisation mixing and FRET transfer once**: one mixing kernel for VV/VH (l1, l2, g,
   r0, rotational operator), and the transfer tensors built in C++ from the FRET kernel
   rather than in ucfret's Python. *Done when*: the Python builder is no longer needed by
   the fixture; parity passes.
6. **Python physics retired**: the bff examples call bff; ucfret's `s88` stays only as the
   frozen reference the parity gates compare against, not as a dependency of bff.

Order: 1 first (no one else's code). Steps 2-5 by agreement with the model-search
session, which owns the graph nodes, one at a time; the owner of each step is named
here before it starts.
